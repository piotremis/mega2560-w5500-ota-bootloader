# Arduino / avrdude compatibility

Baza: oficjalny [Arduino-stk500v2-bootloader](https://github.com/arduino/Arduino-stk500v2-bootloader), commit `06ebf3701162b7b7c557dd64bc10796507dbada5`. Zachowano protokół AVR068, strukturę parsera stanowego i dyspozytora, odpowiedź AVRISP_2 oraz kody komend/statusów. `src/arduino_cases.inc` zawiera pobrane przypadki sign-on i GET_PARAMETER ze zmianą nazw zmiennych. UART, inicjalizacja, ograniczenia pakietów i wspólny zapis stron zostały zrefaktoryzowane dla Mega2560/OTA. Nie jest to niezmieniony upstream ani zamiana na własny protokół.

Ramka: `1B seq len_hi len_lo 0E payload checksum`, checksum XOR wszystkich poprzednich bajtów. Sekwencja jest dowolna i odsyłana bez zmian. Payload wejściowy 1..266 B. Błędny token, checksum albo rozmiar nie wykonują komendy. Brak bajtu przez 2 s kończy sesję i wraca do nadrzędnej logiki boot. Monitor `!!!`, shell, debug strings, pozostałe MCU i programowanie fuse/lock usunięte.

| ID | Komenda | Zachowanie |
|---|---|---|
| 01 | SIGN_ON | OK, długość 8, AVRISP_2 |
| 02 | SET_PARAMETER | ACK jak w bazie; parametry nie zmieniają sprzętu |
| 03 | GET_PARAMETER | build 0, HW 15, SW 2.10; pozostałe 0 jak upstream |
| 04 | SET_DEVICE_PARAMETERS | ACK, MCU stałe ATmega2560 |
| 06 | LOAD_ADDRESS | zapis adresu surowego, bit 31 sygnalizujący rozszerzone adresowanie maskowany |
| 10 | ENTER_PROGMODE_ISP | ACK |
| 11 | LEAVE_PROGMODE_ISP | ACK, powrót do logiki EEPROM/start aplikacji |
| 12 | CHIP_ERASE_ISP | FAILED; standardowy upload używa `-D` |
| 13 | PROGRAM_FLASH_ISP | 1 strona, parzysta długość 2..256; read/modify/erase/write, ochrona boot |
| 14 | READ_FLASH_ISP | 2..256 B, parzyste, obsługa 32-bitowego adresu i całego Flash do 0x3FFFF |
| 15 | PROGRAM_EEPROM_ISP | 1..256 B, pełny zakres 0..4095 |
| 16 | READ_EEPROM_ISP | 1..256 B, pełny zakres 0..4095 |
| 18 | READ_FUSE_ISP | odczyt low/high/extended |
| 1A | READ_LOCK_ISP | odczyt lock |
| 1B | READ_SIGNATURE_ISP | 1E 98 01 |
| 1D | SPI_MULTI | minimalna emulacja transakcji 4 TX/4 RX/start=0: sygnatura i fuse/lock; inne operacje zwracają zera jak baza |

Nieobsługiwane komendy, w tym zapisy fuse/lock, zwracają `STATUS_CMD_FAILED=0xC0`. `STATUS_CMD_OK=0`. Odczyt Flash/EEPROM zawiera status początkowy i końcowy; zapis odpowiada `[cmd, OK]`, zgodnie z bazą i akceptacją avrdude.

LOAD_ADDRESS używa słów dla Flash i bajtów dla EEPROM. Przesunięcie na bajty następuje dopiero po identyfikacji rodzaju pamięci. Usunięto historyczny osobny licznik eraseAddress: kasowana jest faktycznie programowana strona, także przy nieciągłych adresach. Sprawdzane są wyrównanie strony, przekroczenie granic, zerowa długość i przepełnienia adresu. Niepełny zapis UART zachowuje pozostałe bajty strony. OTA ostatnią stronę dopełnia FF.

## Dowody rzeczywistego workflow

Lokalny Arduino AVR Boards **1.8.8**: Mega2560 ma `upload.protocol=wiring`, `upload.speed=115200`, `upload.maximum_size=253952`. Recepta uploadu zawiera `-D` i `-Uflash:w:...:i`. Zweryfikowano również aktualne źródła [avrdude wiring.c](https://github.com/avrdudes/avrdude/blob/7a4c9a21eca02ee4fb251d4861c3b1b7732be378/src/wiring.c) i [stk500v2.c](https://github.com/avrdudes/avrdude/blob/7a4c9a21eca02ee4fb251d4861c3b1b7732be378/src/stk500v2.c).

Wykonany test **avrdude 8.0-arduino.1 -c wiring -D -b115200** przesłał 253952 B Flash (992 strony), przeczytał i zweryfikował cały obraz, następnie zapisał/przeczytał 4096 B EEPROM. Produkcyjny `stk500()`/`stk_command()` działał w natywnej bibliotece C; sprzęt i UART zastąpiono pamięcią i TCP loopback.

Trace tego uruchomienia: SIGN_ON, GET_PARAMETER, ENTER_PROGMODE, READ_SIGNATURE, LOAD_ADDRESS, PROGRAM/READ_FLASH, PROGRAM/READ_EEPROM, LEAVE_PROGMODE. Zapisano `build/tests/avrdude.txt` i `avrdude-trace.json`. SPI_MULTI nie pojawił się w tym konkretnym nowym workflow, ale występuje w generic-command backendzie i starszych wersjach avrdude, dlatego nie został usunięty. Osobne testy sprawdzają jego odpowiedź.

To potwierdza kompatybilność protokołu w przetestowanym workflow, **nie stanowi testu CH340, fizycznego auto-resetu ani wykonywania instrukcji AVR**. Nie sprawdzono wszystkich historycznych wersji avrdude, trybów ISP/HV ani rozszerzeń innych programatorów; nie są one deklarowane jako pełna emulacja STK500 hardware. Bootloader pozostaje programatorem aplikacji Mega2560.
