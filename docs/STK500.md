# STK500v2 compatibility

[Documentation](README.md) / STK500v2

## Implementation basis

The serial implementation derives from [Arduino STK500v2](https://github.com/arduino/Arduino-stk500v2-bootloader),
commit `06ebf3701162b7b7c557dd64bc10796507dbada5`. It retains AVR068 framing,
the parser/dispatcher structure, AVRISP_2 sign-on and command/status identifiers.
`src/arduino_cases.inc` contains adapted sign-on and GET_PARAMETER cases.
UART initialization, bounds checks and page programming were refactored for
Mega2560 OTA. This is an adaptation, not an unchanged upstream build.

## Framing

```text
1B sequence length_hi length_lo 0E payload checksum
```

The checksum is the XOR of all preceding bytes. Any sequence number is accepted
and echoed. Input payloads contain 1–266 bytes. Invalid token, length or checksum
prevents command execution. A 2-second receive timeout returns to boot policy.
The diagnostic `!!!` monitor, shell, debug strings, other MCUs and fuse/lock
programming are removed. This does not remove Arduino IDE Serial Monitor support
from the application.

## Command support

IDs and status values below are hexadecimal.

| ID | Command | Behavior |
|---|---|---|
| 01 | SIGN_ON | OK, length 8, AVRISP_2 |
| 02 | SET_PARAMETER | Acknowledge as upstream; no hardware parameter changes |
| 03 | GET_PARAMETER | Build 0, HW 15, SW 2.10; other parameters return 0 |
| 04 | SET_DEVICE_PARAMETERS | Acknowledge; target fixed to ATmega2560 |
| 06 | LOAD_ADDRESS | Store address; mask the extended-address indicator in bit 31 |
| 10 | ENTER_PROGMODE_ISP | Acknowledge |
| 11 | LEAVE_PROGMODE_ISP | Acknowledge; return to EEPROM/application boot policy |
| 12 | CHIP_ERASE_ISP | FAILED; standard upload uses `-D` |
| 13 | PROGRAM_FLASH_ISP | Even length 2–256; one page; read/modify/erase/write; boot protected |
| 14 | READ_FLASH_ISP | Even length 2–256; 32-bit addresses; Flash through 0x3FFFF |
| 15 | PROGRAM_EEPROM_ISP | 1–256 bytes; addresses 0–4095 |
| 16 | READ_EEPROM_ISP | 1–256 bytes; addresses 0–4095 |
| 18 | READ_FUSE_ISP | Read low/high/extended fuse |
| 1A | READ_LOCK_ISP | Read lock bits |
| 1B | READ_SIGNATURE_ISP | 1E 98 01 |
| 1D | SPI_MULTI | Minimal 4 TX/4 RX/start=0 emulation for signature and fuse/lock; other operations return zeroes |

Unsupported commands, including fuse/lock writes, return `STATUS_CMD_FAILED=0xC0`.
`STATUS_CMD_OK=0`. Memory reads include leading and trailing status bytes;
writes return `[command, OK]`.

LOAD_ADDRESS is word-addressed for Flash and byte-addressed for EEPROM.
Conversion to bytes occurs only after the memory type is known. The page at the
requested address is erased, including for noncontiguous writes; there is no
separate legacy erase counter. Page boundaries, lengths and address overflow
are checked. Partial UART writes preserve unspecified page bytes; OTA pads its
last page with FF.

## Verification scope

The inspected Arduino AVR Boards 1.8.8 configuration uses `wiring`, 115200 baud,
maximum size 253952, `-D` and `-Uflash:w:...:i`. The inspected avrdude revision is
`7a4c9a21eca02ee4fb251d4861c3b1b7732be378`, including
[wiring.c](https://github.com/avrdudes/avrdude/blob/7a4c9a21eca02ee4fb251d4861c3b1b7732be378/src/wiring.c)
and [stk500v2.c](https://github.com/avrdudes/avrdude/blob/7a4c9a21eca02ee4fb251d4861c3b1b7732be378/src/stk500v2.c).

The avrdude 8.0-arduino.1 integration test uses `-c wiring -D -b115200` against
production C with memory and TCP loopback substitutes for hardware. It writes
and verifies 253952 Flash bytes (992 pages) and 4096 EEPROM bytes.
The trace covers SIGN_ON, GET_PARAMETER, ENTER_PROGMODE, READ_SIGNATURE,
LOAD_ADDRESS, PROGRAM/READ_FLASH, PROGRAM/READ_EEPROM and LEAVE_PROGMODE.
Logs are `build/tests/avrdude.txt` and `avrdude-trace.json`.
SPI_MULTI is retained for generic-command/older avrdude paths and tested separately.

This host test verifies protocol behavior, not physical UART timing or AVR
instruction execution. UART0/CH340 uploads were separately tested on hardware
on 2026-09-22. All historical avrdude versions, ISP/HV modes and other programmer
extensions are not covered; this is an application bootloader, not complete
STK500 hardware emulation. See [validation](TESTING.md).
